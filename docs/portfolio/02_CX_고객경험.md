# 02. CX · 고객경험 (Customer Experience)

> **ThinQ Workspace Sentinel** — 요양병원 감염 조기대응 시스템
> LG DX School 5기 캡스톤 · CX/BX 트랙
> 작성 관점: 고객 정의 → 시장 검증 → 여정 설계 → 역할별 경험 → 차별화 → 정직성 → 사업가치

---

## 한 줄 컨셉

> **"보이지 않는 감염 위험을, 보이게 — 그리고 사람이 아니라 공간이 먼저 대응하게."**

감시·대응·기록, 이 세 가지를 모두 **사람에서 공간으로** 넘긴다. 한 명의 간호사가 새벽 3시에 60명을 지킬 수 없던 공간을, 데이터와 가전이 먼저 반응하는 공간으로 바꾸는 것이 이 프로젝트의 핵심 고객경험이다.

## 1. 고객 정의 & 페르소나

요양병원에서는 **돈 내는 사람(결재자)과 쓰는 사람(현장 사용자)이 다르다.** 그래서 CX를 단일 사용자가 아니라 4개 역할로 분해하고, 각 역할의 가장 절박한 Pain에 정확히 대응했다. 페르소나는 임의 설정이 아니라 우리 시스템의 RBAC 역할(`NURSE / FM / DIRECTOR / GUARDIAN`)에서 역으로 도출했다.

| 페르소나 | 프로필 | 가장 큰 Pain | Sentinel의 응답 | 대응 화면 |
|---|---|---|---|---|
| **① 김수진 — 감염관리간호사(ICN)** *핵심 사용자* | 42세, 180병상을 1인 담당 | 야간 발열 환자가 생겨도 **어느 병실이 위험한지 모름**(사후 인지) | HIGH_RISK 병동 즉시 표시 + 가전 자동 환기 | 간호사 대시보드 (`NURSE`) |
| **② 이재호 — 병원장/운영이사** *결재자* | 57세, 작년 노로바이러스 집단감염 피해 | 집단감염을 **2~3주 전에 선제 대응할 방법이 없음** | 외부 신호 급등 시 평균 15~43일 전 사전경보 + 수가·ESG 증빙 | 경영 리포트 (`DIRECTOR`) |
| **③ 최은영 — 보호자** *신뢰 수혜자* | 68세, 85세 어머니 입소 | **정보 부재·연락 불안**(병동에서 무슨 일이 일어나는지 알 수 없음) | 보호자 PWA로 안심 상태 실시간 확인 | 보호자 앱 (`GUARDIAN`) |
| **④ 김민준 — 야간 요양보호사** *현장 운영* | 34세, 야간 단독 근무 | 위험을 **판단할 기준이 없음**(직감 의존) | 5-Tier 알림으로 조치 우선순위 제시 | 시설·가전 제어 (`FM`) |

> 페르소나 카드 원천: [`docs/발표/발표대본_10분_현재덱.md`](../발표/발표대본_10분_현재덱.md) §VII, [`docs/발표/CX_BX_산출문서_심사정합_체크리스트.md`](../발표/CX_BX_산출문서_심사정합_체크리스트.md) P4

### Pain Points 수렴 (ICN 기준 우선순위)

1. 감염 위험을 **미리 알 방법이 없다** — 사후 인지
2. 환기·소독 **타이밍을 경험·직감에 의존**
3. **수기 기록·보고서** 행정부담 (적정성평가 증빙)
4. 가전이 **따로 놀아 통합 제어 불가**

네 페르소나의 Pain은 표면적으로 다르지만, LDA 분석 결과 **한 점으로 수렴**한다: *"실시간으로 다 확인 못 하고, 터진 뒤에야 손쓰고, 증빙할 기록이 없다."* 원인은 단순하다 — **공간의 위험은 연속적인데, 사람의 감시는 단속적이다.**

## 2. 시장·고객 검증 (정량 근거)

페르소나 Pain은 추정이 아니라 **대규모 VOC(Voice of Customer) 데이터**로 검증했다. 표본이 크고, 전 과정이 재현 가능하다(`scripts/cx/run.py`).

### 2.1 VOC 크롤링 → LDA 토픽 모델링

| 단계 | 수치 | 방법 |
|---|---|---|
| 원천 수집 | **78,087건** | 네이버 뉴스·블로그·카페·지식인 + 유튜브 4채널 × 51개 키워드 직접 크롤 |
| 전처리 후 분석 | **75,633건** | HTML 태그 제거 + 중복·단문(노이즈: 장례·광고 등) 필터 |
| 형태소 분석 | NNG·NNP 명사 추출 | Kiwi 형태소 분석기 + CountVectorizer 불용어 제거 |
| 토픽 수 결정 | **n=5** | Perplexity 스캔에서 기울기가 꺾이는 지점 |

5개 페르소나(종사자·시설장·가족·경쟁·정책)로 나눠 각각의 Pain을 토픽으로 도출했다.

### 2.2 핵심 정량 결론

- **부정 감성도(페르소나별):** 종사자 **84.0%** · 정책 79.5% · 시설장 66.5% · 가족 55.2% · 경쟁사 15.5%
- **Pain 정점 영역(부정도 최고):** 시설장 *집단감염* 100% · 종사자 *야간근무* 97% · 가족 *학대* 100% · 환자 *냄새* 89.9%
- **병원장 LDA 분해:** ACTOR 위기대응 30% · Desire 돌봄서비스 16.7% · Goal 예방위생 15% · Pain Points 신고보고의무 12.2% — 이 네 갈래가 그대로 Sentinel이 풀어야 할 과제와 일치
- **시장 규모:** 첫 교두보 전국 **1,342개** 요양병원

> LDA 분석에서 부정 감성이 가장 높은 지점(집단감염·야간근무·증빙 부재)이 정확히 우리가 개입하는 지점이다. **고객이 가장 아파하는 곳에 제품을 놓았다**는 것을 데이터가 증명한다.

## 3. 고객 여정 맵 (Customer Journey)

핵심 시연 스토리는 **2단계 선제대응**으로 설계했다 — 외부 발령만으로 가전을 막 돌리지 않고, 실제 실내 위험을 확인했을 때만 가동한다(오작동 방지). 여정은 *조기경보 → 현장 대응 → 보호자 안심 → 경영 리포트*로 이어진다.

```
[외부 역학 신호]        [실내 센서]          [공간 자동대응]        [사람]
질병청·하수·검색·OTC ─▶ CO₂·온습도·재실 ─▶ tier=max(센서,외부경보) ─▶ 간호사: 환자 곁에
   (15~43일 선행)        (Wells-Riley)        가전 차등 자동제어        보호자: 안심 알림
                                              근거 없는 가전은 OFF      원장: 자동 증빙
```

### 3.1 ICN 하루 동선 (CAM — Customer Activity Map)

| 단계 | 현재 Pain | Sentinel 개입 |
|---|---|---|
| 출근/인수인계 | 데이터 분산, 밤사이 상태 파악 어려움 | 대시보드 요약 |
| 병동 순회 | 환기·온습도 **수기·직감** 점검 | tier 자동 표시 |
| **위험 인지** ⚠️ Pain 폭발 | **근거 부족** | 선제 경보 + 수식 근거 |
| **대응** ⚠️ Pain 폭발 | **수동 지시** | 가전 자동제어 |
| 기록/보고 | 행정부담(적정성평가) | 자동 로그·CSV 증빙 |
| 보호자 응대 | 구두 설명 | PWA 실시간 안심 |

> ICN 하루 6단계 중 **'위험 인지'와 '대응' 두 지점에서 Pain이 폭발**한다(근거 없이 사후에, 사람이 수동으로 움직이기 때문). Sentinel은 정확히 그 두 지점에 개입해 Pain 곡선 전체를 평탄화한다.

### 3.2 시연 시나리오 (3분, 실연동 검증)

출처: [`docs/발표/시연_대본_최종_2026-06-23.md`](../발표/시연_대본_최종_2026-06-23.md)

1. **[0:40–1:05] 1단계 — 선제 발령:** 광주에 인플루엔자 유행. 실내 공기는 정상. 외부 조기경보 발령 → **판정 기준만 선제 상향, 가전은 대기.** "센서가 더 민감해진 게 아닙니다. 같은 환경을 더 보수적으로 판정 — 기준선을 올린 겁니다."
2. **[1:05–1:35] 2단계 — 위험 확인 → 자동 가동:** CO₂ 상승(입김 재현) → 재호흡분율 f↑ → 전파 위험확률 PoI↑ → 등급 상승. **아무도 버튼을 누르지 않았는데 공간이 스스로 대응.** 공기청정 TURBO·환기 MAX·UV-C 살균 가동, 호흡기와 무관한 로봇청소기·스타일러는 **자동 제외**(논문 근거 기반 선택).
3. **[2:00–2:20] 보호자 안심 + 복귀:** 보호자 앱에 *"지역 감염병 확산 감지 — LG ThinQ 가전이 병동 환경 관리를 시작했어요. 따로 하실 일은 없습니다."* CO₂ 정상 5초 지속 시 자동 복귀, 대응 기록 저장.

## 4. 역할별 경험 설계

같은 안전 경험이라도 페르소나마다 다른 차원으로 느낀다(4D-CX: 심리적·물리적·관계적·시스템적). 프론트엔드는 RBAC로 역할별 화면을 분리했다([`frontend/app/`](../../frontend/app/)).

### 4.1 간호사 대시보드 (`NURSE` / `FM` / `DIRECTOR`)
[`frontend/app/dashboard/page.tsx`](../../frontend/app/dashboard/page.tsx)

- **NURSE — 간호사 관제:** "실시간 병동 감시". HIGH_RISK 병동 즉시 표시, 1초 SSE 푸시로 살아있는 센서값.
- **FM — 시설·가전 제어:** "ThinQ 자동 방역". 호실별 가전 맵, 자동제어 모니터링.
- **DIRECTOR — 경영 리포트:** "ESG·ROI 증빙". KPI·수가 가산 증빙 열람.
- 거버넌스: **하이브리드(ALERT/HIGH_RISK 자동, CRITICAL 관리자 승인)** — 자동화와 인간 통제의 균형.

### 4.2 보호자 PWA (`GUARDIAN`)
[`frontend/app/guardian/`](../../frontend/app/guardian/) (home / alerts / ward / settings / login)

- **상태 라벨 최우선 설계:** "24시간 안심 케어 — 보호 중". 불안을 안심으로 바꾸는 것이 목표(심리적 차원).
- **"지금 병원이 하는 일"을 직접 보여줌:** 위험 상승 시 *"LG ThinQ 가전이 병동 환경 관리를 시작했어요 … 따로 하실 일은 없습니다."* — 정보 비대칭 해소(관계적 차원).
- **실시간/끊김 처리(P0):** 데이터 끊김도 정직하게 표시.

### 4.3 경영진 리포트 (`DIRECTOR`)

- 대응 이력을 **초 단위 자동 증빙**으로 축적 → 적정성평가 감염관리 점수 충족 + 행정부담 제거.
- "오늘 병동, 선제 대응 완료" 한 줄 + ESG·ROI 근거 = **구매 결재 명분.**

> 4개 차원이 맞물려 하나의 안전 경험을 만든다: 보호자(걱정→안심) · 시설관리자(공간 자동 안전 유지) · 직원·환자(정보 비대칭 해소) · 시설장(운영·증빙 표준화).

## 5. 차별화 포지셔닝

출처: [`docs/발표/벤치마킹_차별성_포지셔닝.md`](../발표/벤치마킹_차별성_포지셔닝.md)

**핵심 명제: "공기질 자동제어"는 차별점이 아니다. "외부 역학융합 선제대응 + 감염관리 자동증빙"이 차별점이다.**

| 기능 | 이미 상용화 (차별점 ❌) | 우리만 (차별점 ✅) |
|---|---|---|
| PM2.5 → 공청기 자동 풍량 | 코웨이·삼성·샤오미·LG 퓨리케어 | — |
| CO₂ → 환기 자동(DCV) | 빌딩공조 30년 표준(ASHRAE 62.1) | — |
| 멀티가전 루틴 | LG ThinQ ON·SmartThings·Matter | — |
| **외부 역학데이터 → 가전 선제 제어** | **상용 제품 0건** | ✅ **진짜 빈영역** |
| **Wells-Riley 위험도 → 가전 차등 처방** | 학술논문만 | ✅ |
| **5단계 Tier + 적정성평가 자동 증빙** | 없음 | ✅ |

> LG ThinQ ON·퓨리케어도 *"공기 나빠지면 켜기"=사후 반응형*. 우리의 *"유행 감지 시 공기 깨끗해도 미리 켜기"=선제 예측형*은 아무도 안 한다.

### "왜 아무도 안 했나" = 우리의 해자
가치가 없어서가 아니라 **가전사가 구조적으로 못 해서**다: ① 효과 인과 입증 어려움 ② "감염 예방"=의료기기 규제 회피 ③ B2C ROI 안 맞음 ④ 크로스도메인(가전+역학+감염관리)을 한 회사가 못 묶음. → **가전사에겐 벽, B2B SW 솔루션에겐 해자.**

### Prior art / 정직한 차별 (vs 에어딥·KT/SKT 스마트병원)
① **선제성** (외부 역학 융합 vs 실내 모니터링) · ② **자동 액션** (경보로 끝나지 않고 실제 제어) · ③ **벤더 무관** (기존 가전 위에 SW만 얹어 도입비 최소).

## 6. 정직성 원칙 (과대주장 배제)

> **"과대포장은 즉사"** — 거짓말로 보이는 순간 신뢰 전체가 무너진다. 한계는 먼저 인정하고, 그 위에서 강점으로 전환한다.
> 출처: [`docs/발표/정직성_프레이밍_QA.md`](../발표/정직성_프레이밍_QA.md), [`docs/발표/임상근거_검증_2026-06-22.md`](../발표/임상근거_검증_2026-06-22.md)

### 6.1 임상주장 14건 적대적 팩트체크 → 0건 허위
덱·방어논리가 인용한 비의료적 감염저감 근거 **14건**을 4개 병렬 fact-check 에이전트가 1차 peer-reviewed 문헌으로 대조(① 실재 ② 숫자정확 ③ 맥락정직).

> **결과: 9건 ✓검증 · 5건 ⚠보정 · 0건 ✗허위**

### 6.2 시연 중 "정직 자백 3종" (신뢰=가점)
1. **환자 활력징후를 보지 않는다** — 의료기기가 아니라 **공간을 돌본다.**
2. **실제 가전 실증은 코웨이 공기청정기 1종**, 나머지는 제어계획(시뮬). 단 재실 카메라·외부 역학·알고리즘·외부 신호는 **전부 진짜**.
3. 감염을 **"막는다"고 하지 않는다** — 위험을 낮추고 선제 준비할 뿐.

### 6.3 금지 표현 → 정직 대체 (예)

## 7. 비즈니스 가치 (ROI)

출처: [`docs/business/pricing-model.md`](../business/pricing-model.md), [`docs/발표/ROI_감염예방관리료.md`](../발표/ROI_감염예방관리료.md)

### 7.1 지불 근거: "효능"이 아니라 "수가(돈)"
증명 어려운 *감염 예방 효능*을 팔지 않는다. 대신 **즉시 측정 가능한 수가**를 판다.

- **감염예방관리료 등급제** 시행(심평원, 2024.10~) → 감염관리 활동·인력·실적이 **등급**을 가르고, 등급이 곧 **급여(수가)**.
- **의료관련감염 예비평가**(2025~) → 요양병원이 감염관리 "증빙·문서화" 부담을 떠안음.
- 즉 **감염관리 자동 증빙 = 등급 유지/상향 = 수가 = 돈.** 시장이 막 열리는 구간.

### 7.2 ROI 산식 & 회수 12개월
```
연간 가치 V = 등급 상향/유지 수가 차액  +  문서화 인건비 절감  +  집단감염 1건 회피 기대손실
도입비용  C = SW 구독료(연)  +  센서노드 HW(공간당 약 5~7만원, 1회)
회수기간   = C / V   →  목표: 12개월 이내
```
> 200병상 기준, 적정성평가 1등급 유지 시 수가 가산 **연 5~8억원(추정)**으로 도입비 회수. 핵심 가치는 *비용 절감*이 아니라 **리스크 보험**(집단감염 1건 = 병상 폐쇄·소송·평판 손실 회피).

### 7.3 가격 3-tier
| Tier | 대상 | 과금 |
|---|---|---|
| **PoC** | 신규 도입 검증 병원 | 3개월 고정 + 무상 컨설팅 |
| **구독** | 상시 운영 요양병원 | 병상수 × 월정액(예: 8,000~12,000원/병상·월) |
| **건당** | 다지점·간헐 운영 | 자동대응 이벤트 건당 |

> 발표 한 줄: *"저희가 파는 건 '감염 예방'이라는 증명 어려운 효능이 아니라 **감염관리 활동의 자동 증빙**입니다. 도입비는 12개월 내 회수됩니다."*
